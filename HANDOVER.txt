Admin authentication
--------------------
- Existing HBlink4 /admin page remains the administrator entry point.
- Existing local HttpOnly session cookie, CSRF protection, login throttling, mandatory full-config backup gate, config restore protection and fixed restart authorization remain in place.
- auth_provider=cognito uses Amazon Cognito for named administrators and retains the configured local username/password hash as a reserved break-glass path through dashboard/auth_app.py.
- The exact local break-glass username is authenticated locally and is never sent to Cognito. A failed password for that reserved username does not fall through to Cognito.
- Cognito administrators must belong to the configurable HBlink4Admins group.
- Cognito mode provides named users, emailed invitations, temporary-password first login, self-service password reset, admin listing, invite resend and administrator-triggered password reset.
- Cognito first-login Session values remain server-side; the browser receives only an opaque short-lived challenge token.
- Production uses a no-secret Cognito app client; EC2 IAM authorizes server-side administrator authentication and user-management calls.

Current fix: first-login panel teardown
---------------------------------------
- A production first-login test found that NEW_PASSWORD_REQUIRED completed successfully and the authenticated backup gate appeared, but the permanent-password panel remained visible above it.
- Root cause: refreshStatus() hid loginPanel after authentication but did not hide newPasswordPanel/resetPanel in the authenticated branch.
- fix/cognito-first-login-panel explicitly hides both auth-only panels immediately after an authenticated status is established, before showing either the mandatory backup gate or the editor.
- tests/test_admin_ui_state.py guards the authenticated-state transition so the first-login panel cannot regress into the authenticated UI again.
