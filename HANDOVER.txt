Admin authentication
--------------------
- Existing HBlink4 /admin page remains the administrator entry point.
- Existing local HttpOnly session cookie, CSRF protection, login throttling, mandatory full-config backup gate, config restore protection and fixed restart authorization remain in place.
- auth_provider=cognito uses Amazon Cognito for named administrators and retains the configured local username/password hash as a reserved break-glass path.
- The exact local break-glass username is authenticated locally and is never sent to Cognito. A failed password for that reserved username does not fall through to Cognito.
- Cognito administrators must belong to the configurable HBlink4Admins group.
- Cognito challenge sessions remain server-side; browser challenge tokens are opaque and short-lived.
- Cognito access tokens used for self-service security/profile operations are stored only in the existing in-memory administrator session, never browser JavaScript or persistent files.
- dashboard/admin_app.py is the top-level ASGI application. It composes the password/break-glass/TOTP layer, WebAuthn security-key layer and administrator profile/invitation layer.

Admin onboarding and optional MFA
---------------------------------
- NEW_PASSWORD_REQUIRED completion tears down the permanent-password panel as soon as an authenticated session exists.
- Optional TOTP authenticator-app MFA can be enrolled, verified and disabled by Cognito administrators. Pool-level MFA remains OPTIONAL.
- FIDO2/WebAuthn security-key/passkey registration, listing/removal and sign-in use Cognito USER_AUTH/WEB_AUTHN and support YubiKey/platform passkeys.
- WebAuthn browser ceremonies remain native navigator.credentials operations. HBlink4 never receives or stores authenticator private keys.
- Cognito can retain TOTP and one or more WebAuthn credentials for the same administrator account; the UI reports those methods independently.
- Once at least one MFA/security-key method is configured, the account-security card collapses to a compact summary and Change MFA button. Expanding it exposes TOTP and WebAuthn management controls; Done collapses it again.
- Cognito administrator profile cleanup uses standard attributes: given_name, family_name, nickname (callsign), plus existing email.
- Missing first name, last name or callsign can be collected and saved before an administrator sends an invitation.
- Once first name, last name, callsign and email are present, the profile card collapses to an identity summary and Change administrator profile button. Incomplete profiles remain expanded until completed.
- Personalised invitations collect invitee first name, last name, callsign and email and store those values in Cognito standard attributes.
- Dashboard invitations suppress Cognito stock invite delivery, create the temporary password server-side, and send a personalised SES multipart HTML/plain-text email.
- Invitation sender is HBLINK4_ADMIN_INVITE_FROM; production is webmaster@sgars.vk2ale.com.
- Invitation email includes https://dmr.vk2ale.com/admin, temporary credentials, 12-character permanent-password rules, 7-day temporary-password validity, optional MFA information, and the inviting administrator's name/callsign signature. Reply-To is the inviter's Cognito email.
- The local PBKDF2 break-glass account intentionally has no Cognito profile/MFA requirement and cannot sign personalised Cognito invitations.
- RF/core routing code remains unchanged.

Invite feedback follow-up
-------------------------
- Production testing on 2026-08-29 exposed a UX bug after a personalised invitation was sent: the invitee fields remained populated and the only success indication was the global message banner at the top of the page, outside the invite form viewport.
- This ambiguity can cause an administrator to click Send invitation a second time because there is no local confirmation that the first request completed.
- Branch fix/admin-invite-feedback adds dashboard/static/admin_invite_feedback.js.
- The helper places an aria-live status beside Send invitation, changes the button to Sending... while the request is active, mirrors success/failure locally, clears all invitee fields on confirmed success, and changes the button to Send another invitation.
- dashboard/admin_app.py cache-busts all injected admin helper scripts so browsers cannot retain stale invitation/MFA/profile code after deployment.
- dashboard/static/admin_profile_compact.js provides the completed-profile collapse without changing Cognito profile storage or invitation semantics.
- Static regression coverage is in tests/test_admin_invite_feedback.py, including invitation feedback, compact completed profile, compact configured MFA and WebAuthn count integration.

Safety notes
------------
- Full configuration backups contain passphrases and must be stored securely.
- Do not expose password hashes, Cognito client secrets, access tokens, WebAuthn private material or full config through public dashboard APIs.
- Preserve HBlink4 hot-path behaviour; administrator/Cognito/SES calls are control-plane only.
- Never make an authentication failure for the reserved local username fall through to Cognito; keep both paths explicit and auditable.
- Keep MFA optional at user-pool level unless a future reviewed change explicitly chooses enforcement.
