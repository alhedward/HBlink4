Admin authentication
--------------------
- Existing HBlink4 /admin page remains the administrator entry point.
- Existing local HttpOnly session cookie, CSRF protection, login throttling, mandatory full-config backup gate, config restore protection and fixed restart authorization remain in place.
- auth_provider=local uses the existing PBKDF2 administrator credential and remains the default/fallback.
- auth_provider=cognito uses an Amazon Cognito User Pool behind the same HBlink4 login UI.
- Cognito administrators must belong to the configurable HBlink4Admins group.
- Cognito mode provides named users, emailed invitations, temporary-password first login, self-service password reset, admin listing, invite resend and administrator-triggered password reset.
- Cognito first-login Session values remain server-side; the browser receives only an opaque short-lived challenge token.
- Optional Cognito app-client secret support exists, but the planned production deployment intentionally uses no client secret; EC2 IAM authorizes the server-side admin authentication operations.

Current fix
-----------
- fix/cognito-invite-email-verification explicitly marks invited administrator email attributes verified in AdminCreateUser.
- This makes Cognito ForgotPassword/AdminResetUserPassword recovery delivery reliable for invited administrators.
- The feature workflow ran the complete regression suite successfully before committing the fix.
