RF capture findings
-------------------
- Operator supplied hblink9990.pcap containing one clean TG9990 exchange.
- Capture contained 170 inbound DMRD packets and 170 outbound replay packets plus normal keepalive traffic.
- The recorded call was about 10.26 seconds, one stream, 168 voice bursts.
- Parrot replay packets were byte-for-byte identical to the incoming DMRD packets, confirming the ordinary echo path does not modify AMBE payloads.
- 504 captured 72-bit AMBE frames round-tripped through the HBLink/dmr_utils3 DMR deinterleave/reinterleave algorithm with zero mismatches.
- Captured TS2 voice sequence/header layout matches the generated telemetry call shape, so the HomeBrew 60-ms burst wrapper is no longer the leading suspect.

OpenDMR findings
----------------
- Voice source assets were generated offline from Australian-English gTTS PCM using OpenDMR pinned at d28164b39ba4d91ad5948ff22707937f8944f70f.
- OpenDMR opendmr.cpp serializes encoder b[0..8] parameters naively as contiguous fields with lengths 7,5,5,9,7,5,4,4,3.
- The bundled OP25-derived MBE encoder's own encode_49bit() uses a different AMBE bit placement: high bits are placed in positions 0..34 and low-order bits are distributed through positions 35..48.
- This mismatch can yield structurally valid Golay/FEC and DMR interleave while scrambling the actual 49 AMBE voice parameter bits. It is the leading root-cause candidate for the garbled/backwards-sounding telemetry.
- Earlier OpenDMR B-block Golay alignment defect was already repaired in HBlink4; that repair alone did not restore intelligible RF speech.
- Do not regenerate TTS unless necessary. The current working hypothesis is that existing AMBE frames can be losslessly decoded back to the original nine b[] parameter values using the wrapper's wrong sequential layout, then repacked with encode_49bit() and rebuilt with correct FEC.

Admin voice telemetry control
-----------------------------
- dashboard/parrot_admin.py exposes and changes only parrot.voice_telemetry_enabled.
- Writes require authenticated admin session, CSRF, the existing full-config backup gate and a matching config revision.
- Config replacement is atomic and keeps a complete pre-change .bak.
- Apply calls the existing fixed-command restart path and verifies hblink4.service becomes active.
- Cognito administrators and the local PBKDF2 break-glass administrator can use the control.
- Echo enablement is independent; disabling spoken telemetry leaves TG9990 echo working.

TG9990 parrot behaviour
-----------------------
- Local group-call service only; never routed to external DMR networks or ordinary repeater fan-out.
- 2 second playback delay, 60 ms packet cadence and 120 second recording cap.
- Long echoes no longer false-cancel when normal stream-state hang-time cleanup releases the originating slot.
- Dashboard activity shows actual TS1/TS2 and returns terminal state to Ready.
- Voice telemetry follows only a successful echo and yields to new RF without turning the completed echo into Test cancelled.
