Parrot / echo service
---------------------
- HBlink4 has an in-process local DMR parrot service based on the classic HBlink3 playback behaviour without running a second legacy HBLink daemon.
- hblink4/parrot.py records accepted local group-voice DMRD frames and replays the original packet sequence to the originating repeater/hotspot at the configured cadence after a proper voice terminator.
- The parrot is configurable through a top-level `parrot` object. Production uses TG9990, a 2-second delay, 60-ms packet cadence and a 120-second recording cap.
- When enabled, the configured parrot TG is accepted as a local service even when absent from normal repeater TG allow-lists.
- The parrot TG receives an empty normal route cache: it is never fanned out to another local repeater, HomeBrew outbound, or OpenBridge trunk.
- A numerically identical TG received from an external trunk does not invoke the local parrot.
- Playback is cancelled if the originating repeater disconnects or reuses the slot before/during echo.
- Calls that exceed the configured recording cap or end through timeout/fast-terminator handling are discarded instead of replayed incompletely.
- Regression coverage for RF/core behaviour is in tests/test_parrot.py; operator documentation is docs/parrot.md.

Dashboard visibility follow-up
------------------------------
- The original TG9990 rollout did not expose the local service in the dashboard UI, because TG9990 is intentionally absent from the ordinary routed talkgroup ACLs.
- Branch fix/parrot-dashboard-visibility adds a public `/api/local-services` projection that reads only non-secret enabled local-service metadata from the live HBlink4 config.
- The endpoint never returns repeater passphrases or the complete configuration.
- dashboard/static/local_services.js renders an explicit public `Local DMR Services` entry for `TG9990 — Parrot / Echo Test` plus a compact header badge.
- The same helper adds a `Local DMR services` card to the administrator view, explicitly marking TG9990 as local-only and excluded from ordinary repeater/external-network routing.
- Public and administrator HTML inject the local-services helper with a cache-busted asset version and no-store HTML response.
- Regression coverage is in tests/test_parrot_dashboard.py.

Authentication and administrator controls
-----------------------------------------
- /admin uses Cognito for named administrators and retains the configured local username/password hash as a reserved local break-glass path.
- The reserved local username is never sent to Cognito; a failed password for that username never falls through to Cognito.
- Cognito administrators must belong to HBlink4Admins.
- Cognito access/challenge tokens remain server-side behind the existing HttpOnly/CSRF session layer.
- Optional TOTP and WebAuthn/YubiKey/passkey management are available to Cognito administrators.
- Completed administrator profile and configured MFA/security-key panels collapse to compact Change controls.
- Personalized administrator invitations use SES from webmaster@sgars.vk2ale.com and clear the invite form with local success/failure feedback after submission.

- Treat the live EIP association as the authoritative production color.
- Keep external network TGs and local service TGs explicitly isolated; the parrot must never become a transit/bridge path.
