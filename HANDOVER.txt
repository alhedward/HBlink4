Admin authentication
--------------------
- Existing HBlink4 /admin page remains the administrator entry point.
- Existing local HttpOnly session cookie, CSRF protection, login throttling, mandatory full-config backup gate, config restore protection and fixed restart authorization remain in place.
- auth_provider=cognito uses Amazon Cognito for named administrators and retains the configured local username/password hash as a reserved break-glass path.
- The exact local break-glass username is authenticated locally and is never sent to Cognito. A failed password for that reserved username does not fall through to Cognito.
- Cognito administrators must belong to the configurable HBlink4Admins group.
- Cognito challenge sessions remain server-side; browser challenge tokens are opaque and short-lived.
- Cognito access tokens used for self-service security/profile operations are stored only in the existing in-memory administrator session, never browser JavaScript or persistent files.
- dashboard/admin_app.py is the top-level ASGI application. It composes the existing password/break-glass/TOTP layer, WebAuthn security-key layer and administrator profile/invitation layer.

PR #6: admin onboarding and optional MFA cleanup
------------------------------------------------
- Fixes the production-observed first-login bug where NEW_PASSWORD_REQUIRED completed successfully but the permanent-password panel remained visible above the authenticated backup gate.
- refreshStatus() now tears down newPasswordPanel/resetPanel whenever an authenticated session is established.
- Adds optional TOTP authenticator-app MFA. Administrators can enroll/verify/disable it themselves; pool-level MFA is intended to be OPTIONAL, not mandatory.
- Adds FIDO2/WebAuthn security-key/passkey registration, listing/removal and sign-in through Cognito USER_AUTH/WEB_AUTHN, suitable for YubiKey and platform passkeys.
- WebAuthn browser ceremonies remain native navigator.credentials operations. HBlink4 never receives or stores authenticator private keys.
- Adds lazy Cognito administrator profile cleanup using standard attributes: given_name, family_name, nickname (callsign), plus existing email.
- If an authenticated Cognito administrator is missing first name, last name or callsign, the dashboard can collect and save those fields before that administrator sends an invitation.
- Future dashboard invitations collect invitee first name, last name, callsign and email and store those values in Cognito standard attributes.
- Future dashboard invitations suppress Cognito's stock invite delivery, create the temporary password server-side, and send a personalised SES multipart HTML/plain-text email.
- Invitation sender is configured by HBLINK4_ADMIN_INVITE_FROM; production target is webmaster@sgars.vk2ale.com.
- Invitation email includes https://dmr.vk2ale.com/admin, temporary credentials, 12-character permanent-password rules, 7-day temporary-password validity, optional MFA information, and the inviting administrator's name/callsign signature. Reply-To is the inviter's Cognito email.
- The local PBKDF2 break-glass account intentionally has no Cognito profile/MFA requirement and cannot sign personalised Cognito invitations.
- RF/core routing code is unchanged.

Infrastructure dependency before deploying PR #6
-------------------------------------------------
- hblink-website must upgrade the existing user pool from LITE to ESSENTIALS in place before WebAuthn is used.
- User-pool MFA must be OPTIONAL with software-token MFA enabled.
- Sign-in policy must allow PASSWORD and WEB_AUTHN and the app client must allow ALLOW_USER_AUTH while retaining ALLOW_ADMIN_USER_PASSWORD_AUTH.
- WebAuthn relying-party ID must be dmr.vk2ale.com with user verification required. Production deployment should verify the desired passkey factor configuration after apply.
- sgars.vk2ale.com must be an SES-verified/DKIM-authenticated identity managed through Route 53, and the EC2 runtime role must be able to send only the required SES mail path.
- Cognito email delivery for recovery/reset mail should use the verified SGARS sender rather than the default Cognito no-reply address.
- The dashboard service environment must provide HBLINK4_ADMIN_INVITE_FROM=webmaster@sgars.vk2ale.com and HBLINK4_ADMIN_URL=https://dmr.vk2ale.com/admin.
- EC2 Cognito IAM must include the additional admin operations used by personalised invite resend/profile management where IAM authorization applies.

- Never make an authentication failure for the reserved local username fall through to Cognito; keep both paths explicit and auditable.
- Keep MFA optional at user-pool level unless a future reviewed change explicitly chooses enforcement.
